Contract Roles Analysis

Inspect access-control roles of a smart contract on Ethereum, Base, Polygon, or Arbitrum — fully in your browser. The only network traffic is to the Etherscan V2 API, using the key you provide.

1. Connection

2. Role events

The events to discover via the explorer's getLogs API. Tick whether each should be treated as granting and/or revoking a role, and choose which argument is the role (bytes32) and which is the account (address). Seeded with the OpenZeppelin RoleGranted / RoleRevoked events.

3. Role constants (optional)

Map human-readable names to their bytes32 values. Compute keccak256(name) automatically or paste a raw value. Used to label results and to verify membership.

4. Membership check (optional)

The view method used to confirm whether an account currently holds a role. Optionally list extra candidate addresses (one per line) to check directly — useful for roles granted via internal calls the scan can't see.

5. Scan & analyze

The explorer getLogs API discovers candidate role holders from the events above over the block range, then hasRole confirms current membership — both through the same API key. Leave "To block" blank to scan up to the latest block.
